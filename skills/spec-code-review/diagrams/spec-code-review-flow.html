The panel flow

Three stages and an optional fourth, over a change, a pull request, a branch, or the whole project. The repo's own checks decide everything mechanical; every kept finding is confirmed by someone who did not write it; the run advises, the human decides.

Resolve the target

prgh pr view · clean tree → auto-checkout · dirty → refuse
projecttracked files, largest-first, cap 30

Stage 1 — mechanical gate

Repo's own checksMakefile · npm · cargo · go · pytest/unittest — plus bash -n and secret-shape scans on the change
Red gate ends the runFailing checks are the findings; reviewers are never spent. Empty detection is not a pass — the documented check runs.

Stage 2 — panel · triage · confirmation

Reviewers in parallelcorrectness · security · quality & tests — one general reviewer on small targets. Zero findings is success.
Triage editordedupe across lenses; drop style, speculation, pre-existing — every drop with a one-line reason.
Independent confirmerper finding, intent-blind: verified / unconfirmed — never silently dropped.

Stage 4 (optional) — the fix loop

bounded · default 2 rounds · or fix_from continuation
Fixerworking tree only · never commits · never weakens a test

Gate re-runsfailures become findings the fixer must clear
Fresh eyesthe fixer's paths only — NEW defects
unresolved & rounds left ↺ back to the fixer

Stage 3 — synthesis

Assessmentrisk (low/med/high) · test gaps · residual risks · verdict · notCovered separates clean from unlooked
Recommendationmerge · fix-first · human — fixes stay uncommitted; the commit is the user's
