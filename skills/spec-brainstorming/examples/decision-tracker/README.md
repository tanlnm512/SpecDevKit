# Example: decision-tracker — a completed design spec

The green fixture of this skill: what a finished run's artifact
looks like. `decision-tracker.md` is the reference output of the
B1–B3 flow in `evals/cases.md` (the "CLI that tracks my team's
decisions" idea) — a blend direction, honestly recorded, with
every Cynic dealbreaker carried into the risk table. It satisfies
every criterion in `gates/handoff.md`; the test suite pins that
it does.

Use it to calibrate: this is the shape, density and honesty a
handoff-ready design spec carries — not a requirements doc (that
is `/spec`'s to shape with the user), and not a transcript (the
conversation stays in the conversation).
