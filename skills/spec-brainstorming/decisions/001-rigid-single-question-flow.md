# D-001: One question at a time

Stage 1 asks exactly ONE clarifying question — no lists, no
numbered options, no multi-part forms — and stage 4 refines with
single questions, strictly one per turn. This is deliberately
opposite to spec-to-prod's batched grilling rounds (its ADR-009),
and the difference is the point: a brainstorm's answers reshape
what the next question should be. A batch freezes the question
set before the first answer lands — it forces premature
commitment precisely when the idea is too soft to commit — while
a single well-chosen follow-up can retire three would-have-been
questions. The constraint also respects the medium: a brainstorm
often happens on a phone, between other work, one answer at a
time.

**Why**: ideas arrive half-shaped; the questioning must be
reshapeable with each answer. Batches are for requirements that
already know what they don't know.

**Cost if wrong**: well-formed ideas get a slower session than a
batch would give (mitigated: the soft cap and the user's freedom
to answer fast — "just build the obvious thing" is a valid stage-4
answer that collapses the refinement). The rigidity is the
product; the escape hatch is brevity, not batch.
