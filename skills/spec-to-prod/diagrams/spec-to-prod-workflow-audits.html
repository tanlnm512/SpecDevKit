Before-Audit & Closing-Audit Gates

Zoom-in of the before-audit and closing-audit nodes in the workflow graph — see spec-to-prod-workflow-overview.html for the full graph these two once-only audits sit inside. Each audit runs exactly once: the before-audit when the execution frontier first becomes eligible (verify done, before any implementer spawns; record Before-audit: passed @ - where no git sha exists), the closing audit after every task in task.md is implemented. In a non-git repo the git gates (clean tree, isolated branch, scope baseline, the commit itself) degrade to explicit SKIPPED (not a git repo) notices — never silent passes. Failure loops back through fix rounds (cap 5/task), never a per-task audit.
